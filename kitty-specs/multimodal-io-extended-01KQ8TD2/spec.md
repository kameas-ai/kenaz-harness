# Spec: Multimodal I/O — outbound generation and extended file types

**Status**: draft · **Owner**: alecfeeman

## 1. Why

The existing `multimodal-io-01KQ5GW4` spec covers inbound multimodal (images + PDF + drag-dropped text files). Out of scope there: outbound model→file generation, audio I/O, video, and broader file-type coverage. This mission picks up those gaps so the harness handles "nearly every realistic file type."

## 2. Goals

- **Outbound image generation**: when the model produces an image (Anthropic / OpenAI image-generation; tool-emitted base64), capture it as a binary artifact viewable in the Artifacts tab and inline in the message bubble.
- **Outbound document generation**: same for PDF/HTML produced by tools or model output.
- **Audio I/O**: send audio (m4a, wav, mp3, flac) as a multimodal block when the model supports it (Realtime, GPT-4o-audio, Bedrock); receive audio responses as artifacts.
- **Video I/O**: send video (mp4, webm) where the model supports it (Gemini 1.5/2); receive frames or transcripts as artifacts.
- **Office documents**: spreadsheets (XLSX/CSV), Word (DOCX), Keynote/PowerPoint — sent as document blocks where supported, otherwise as text-extracted context attachments via a new pluggable extractor.
- **Source-code archives**: zip / tar / tarball files unpacked locally and inlined as a multi-file context bundle (with a per-file size cap).
- **Markup formats**: HTML / XML / SVG / Mermaid as inline text + rendered preview when present.
- **Per-provider capability gating**: the existing `core/llm/capabilities/` registry expands to enumerate audio/video/document subtypes; sends unsupported file types are rejected with a clear "switch to a model with audio support" error.

## 3. Non-goals

- Real-time voice (separate mission).
- Image generation tooling (Stable Diffusion local install, etc.) — only model-native generation.
- DRM-protected formats.
- Extractors that require headless browser execution (HTML rendering with JS).

## 4. Functional requirements

| ID | Requirement | Status |
|---|---|---|
| FR-001 | New `core/llm.ContentBlock` types: `audio`, `video`, `document_extracted`. Adapters serialise per-provider. | proposed |
| FR-002 | Outbound capture pipeline: when an assistant turn or tool result contains binary content (image/PDF/audio/video), capture as artifact via existing CAS path. | proposed |
| FR-003 | New `core/extractors/` package with pluggable extractors for: docx, xlsx, pptx, csv, html, xml, archive (zip/tar). Each extractor produces text + optional structured metadata. | proposed |
| FR-004 | ChatInput.vue accepts the extended file-type set via paperclip + drag-and-drop. | proposed |
| FR-005 | MessageBubble renders inline previews for image/audio/video where the browser supports the format; document-style attachments show a chip + open-in-preview affordance. | proposed |
| FR-006 | Capability gate rejects sends to models that don't support a given modality with a typed error surfaced as a toast in the chat surface. | proposed |
| FR-007 | Per-file-type size limits: image 20 MB, PDF 50 MB, audio 100 MB, video 500 MB, archive 50 MB. Configurable per Settings. | proposed |
| FR-008 | Archive extraction: zip/tar files are unpacked, per-file size capped at 1 MB, total inlined content capped at 5 MB; over-cap files emit a "[truncated]" placeholder. | proposed |

## 5. Non-functional requirements

| ID | Requirement | Threshold | Status |
|---|---|---|---|
| NFR-001 | Extractor latency. | p95 ≤ 2 s for any single file ≤ size limit. | proposed |
| NFR-002 | Inline preview render. | First-frame ≤ 100 ms after attachment. | proposed |

## 6. Success criteria

- Sending a 10 MB MP4 to Gemini 2 Flash produces a model response describing the video content.
- Sending the same file to Sonnet 4.6 produces a clear "this model doesn't support video" error before the wire call.
- DOCX upload with embedded tables produces a context attachment with table data preserved as Markdown.
- Image generated by an OpenAI tool turn appears in the Artifacts tab with mime `image/png`, viewable in the artifact preview.
