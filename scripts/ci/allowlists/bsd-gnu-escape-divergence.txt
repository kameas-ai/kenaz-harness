# BSD/GNU whitespace-escape-divergence class (Finding #96,
# CI-gate-hardening, 2026-09-14).
#
# Enforced by scripts/ci/check-bsd-gnu-escape-divergence.sh. A grep/sed
# pattern or replacement spelling a whitespace escape (\t, \n, \r) as
# the two-character backslash-letter sequence inside a plain '...' or
# "..." string, rather than a real byte via ANSI-C ($'...') quoting.
# The meaning of the two-character form is not portably defined between
# BSD (macOS, where gates are written) and GNU (Linux, where gates are
# enforced) userlands — see that script's own header for the two
# confirmed instances that motivated this gate.
#
# Format: one entry per violation, keyed by `<file>: <description>`
# (NOT file:line — see i16-config-nil-coverage.txt's header for why a
# line-number key self-invalidates on any unrelated edit above the
# entry; this gate is designed keyed from the start), copied verbatim
# from the gate's FAIL output, followed by a `#` comment carrying the
# DATE, the BLOCKER, and the change that will delete the line.
# Allowlists shrink monotonically — an entry that no longer corresponds
# to a real occurrence is STALE and fails the gate.
#
# EMPTY, and it must stay that way: both confirmed instances
# (check-transport-parity.sh:92, check-cedar-gate-arguments.sh's
# clause-4 nested-call-permit sed script) were fixed in the same
# commits that introduced/audited this gate. There is no known
# legitimate reason to spell a grep/sed whitespace escape any other way
# than ANSI-C quoting.
