## 1. What a green suite here does NOT mean

Recorded first, because it is the most load-bearing thing in this document.

- **`check-codegen.sh` cannot see hand-edited bindings.** It hashes the Go
  binding *source* against a committed hash the author restamps with
  `--update-wailsjs-hash`. A hand-written `frontend/wailsjs/**` passes.
  Proven this campaign: an agent hand-mirrored `models.ts`, the gate went
  green, and real regeneration differed in 88 lines. **Open, ungated.**
- **`check-no-unwired-gates.sh` is package-blind.** It greps bare symbols, so
  a new `pkgA.WithCedarGate` silently satisfies an allowlist entry for an
  unrelated, still-unwired `pkgB.WithCedarGate`. Hit for real by GA01.
  Same class as I10's `has_real_callsite` blindness. **Open, ungated.**
- **`migrations.Registry.VerifyLedger` has zero non-test callers**, so
  content-hash drift between a recorded migration and the shipped definition
  is never detected at boot. This is what made the prod-database incident
  (§5) a forward risk rather than a cosmetic one. **Open, ungated.**
- **Gate falsifiability is still partial: 22 of 36** gates carry a
  planted-violation proof (recount by ZD13 UNIT-4 via `comm`; the previous
  figure of 21/34 was arithmetic error, and it found a 14th ungated script,
  `check-no-model-family-literals.sh`). A gate with no proof is a gate nobody
  has shown can fail.

## 3. Defects found by INTEGRATION, not by any agent

These are the argument for verifying on the merge target. Each was invisible
to the branch that caused it, because no branch contained the other's work.

1. **Data race** — `bootAPIWithCore` leaked a fleet `ConfigPoller` past its
   test; it called `keyring.Get()` for the life of the test binary while
   later tests called `keyring.MockInit()` (a package global). Presented as an
   unrelated `TestKeychainDelete_NotFoundIsSilent` failure and never
   reproduced in isolation. **Fixed.** *At least nine other `core/rpc` test
   files construct the API against a real Core and never `Shutdown` — the
   same latent leak. Recorded, not fixed.*
2. **Build failure** — ZE14's round-trip test called `saveGraph(spec)` after
   GA01 changed it to `saveGraph(ctx, spec, initiator)`. **Fixed**, passing
   `"user"`: `"model"` would be denied by GA01's own AC-004 and fail for an
   unrelated reason.
3. **Semantic conflict** — Z101 pinned gemini `structured_output=false`;
   ZE14 flipped it true. **Fixed** toward `true`, verified against
   `gemini/wire.go:379,398` actually setting `ResponseSchema`.
4. **Migration-count arithmetic** — three missions each bumped the ledger from
   a different base (43/44/45). True merged value is **51**. **Fixed.**
5. **Test-fake publication race** — the sampling stub bumped its call counter
   before storing the request the test polls for. **Fixed.**
6. **Layering violation** — `core/event/log` imported `core/fleet`. **Fixed**
   (§2, ZA10).
7. **Gate false positive** — `check-single-move-writer.sh` walked
   `.claude/worktrees/**` and counted each agent's repo copy as an extra
   writer, failing on a clean tree. **Fixed.**

## 4. Process findings

- **Worktrees cannot see `docs/` or `kitty-specs/`** — both are gitignored,
  so a fresh `git worktree add` starts without them. Every agent had to copy
  its own spec in. More seriously, **coordination messages citing those files
  are unverifiable from inside a worktree.** ZD13 correctly refused a
  heads-up from the coordinator as a possible prompt injection, and
  duplicated work as a result. The defensive instinct was right; the setup
  is wrong. Either ship specs into worktrees or stop citing unreachable paths.
- **Agent reports contain confabulated verification details.** One reported
  confirming a migration ledger "unchanged at 45" from a worktree whose file
  read 43. The substantive claim held; the verification did not happen. Treat
  numeric claims as unverified until re-run on the merge target.
- **A pre-blessed cut and a silent cut look identical in a summary.** ZE14's
  distinction between "in `plan.md`'s cut-line table" and "not in it" is the
  only thing separating an accepted trade from an unnoticed hole. Keep asking
  for it explicitly.

## 5. The production-database incident (resolved)

A sub-agent ran `wails generate module` without overriding
`HOME`/`KENAZ_HARNESS_ENV`. That command executes `main.go`'s
binding-introspection path, which opened `~/.kenaz/harness/prod/data.db` —
a real profile with 15 sessions — and applied six `event-log/0100–0105`
migrations to it.

Additive only; nothing destroyed. The hazard was forward-looking: IDs
recorded as `applied` from *uncommitted* code, a runner that keys on ID, and
`VerifyLedger` with zero callers, so the shipped definitions would have been
skipped on that install with nothing noticing — and the mission itself had
already slated one of those seeds (`retention_config`'s `keep_all`) for
correction in a later unit.

Remediated after proving against `testdata/upgrade/v0.64.1/dump.sql` that
none of the six tables exist in any shipped schema: dropped the six tables,
deleted the six ledger rows, backup retained. Sessions/projects/graph events
untouched; `PRAGMA integrity_check` ok. Dev unaffected; no other agent wrote
to prod.

Doctrine added to `CLAUDE.md`. **The class is not closed**: nothing prevents
the next person doing this. The real fix is either making the binding
introspection not open a database, or a CI/pre-commit guard. Unowned.
