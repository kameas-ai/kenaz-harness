## P1 — Tool schemas cost ~220k tokens on EVERY model call; models ≤200k are unusable

**Numbers (OpenRouter `usage` frames in the app log):** first turn, one
user message ("Reply with exactly the word pong"), system prompt
2,292 chars (`agentgraph.model.call … system_prompt_len=2292`,
`messages=1`): `prompt_tokens=224798`, `cached_tokens=0`, cost $0.1124
on Haiku. Every later call is 225–237k. `llm.request.tools count=143`:
outlook 94, kenaz 27, filesystem 14, harness-self 7, fetch 1. By
subtraction the tool-schema block is ~220k tokens; no adapter sends
`cache_control` (grep: none in core/llm).

**Consequences seen live:**
- A 13-call conversation of one-line answers cost $1.51.
- The "This conversation is getting long" banner fired on turn 1
  (`LongSessionNudge.vue`, token-count threshold; 23 % of a 1000k bar).
- The scheduled chat (below) can never run on the profile default model.

**This is a product decision (toolset Phases A–C, Q1–Q13), not a bug
fix:** tool-schema budget / deferred tool loading, per-session tool
enablement defaults (Outlook's 94 tools on by default is the bulk),
and prompt caching for Anthropic-family models via OpenRouter.
Surfaced to the owner; no code change in this PR.

## P1 — Scheduled chat always fails on the profile default model, is mis-diagnosed, retried 4× and only surfaces as a 10-second toast

**Seen:** "Dogfood sentinel" (Run now at 21:14:48, cron at 21:15:00 and
21:18:00) — every run: `openrouter.http.error model=aion-labs/aion-2.0
status=400 body="This endpoint's maximum context length is 131072
tokens…"`, then `agentgraph.loop.body.retry` ×4 inside 2 s, then
`chat.run.complete reason=backend-error err="session has hit its
context window and compaction is unavailable"` on a BRAND-NEW empty
session, delivered as a warn toast for 10 s. The Schedules row shows no
last-run state; Runs tab had nothing to show.

**Causes:**
- `core/agentgraph/compaction/session_engine.go:561` classifies any
  provider error containing "context length" as `cap_exceeded` →
  `compaction.ErrSessionFull` (`chat_runner.go:2096`), even when the
  session has no history and the overflow is the tool-schema block. The
  message blames the user's conversation for a request the harness
  built.
- `core/agentgraph/exec_control.go:947 isTerminalNodeError` treats a
  provider HTTP 400 as retryable (`NodeErrorPolicyRetryOnce` re-fires;
  the log shows four model calls in two seconds for one run).
- Model choice: "Leave blank to use the active default" resolved to
  `aion-labs/aion-2.0` (131k) — the profile's first/default model, not
  the model the user was chatting with. The form should show which
  model "active default" resolves to.
- `core/rpc/chat_run_dispatcher.go` delivers failures only via
  `TopicScheduledChatBanner` → `useEventToasts.ts` 10 s toast. The
  schedule entry carries no `last_run_at/last_status/last_error`.

**Fix shape:** (1) a 4xx `invalid request` from the provider is
terminal — no loop retry; (2) classify "maximum context length" on a
request whose history is empty/small as a *request-too-large* error
("The request (tool definitions + context) exceeds <model>'s N-token
window; pick a larger model or disable tools") — never `ErrSessionFull`
when the prompt is dominated by tool schemas; (3) persist last-run
status on the scheduled-chat record and render it in the Schedules row
(status, time, error) with the toast kept; (4) the form resolves and
displays the "active default" model id.

## P1 — Footer cumulative tokens/cost under-count tool-loop calls (~30 % missing)

**Seen:** session footer `2,078,630 tok · $1.0439` when the provider had
reported 13 calls / 3,000,619 tokens / $1.5059 for the session
(`agentgraph.model.result` lines; per-call list in the transcript).
Ratio 0.693 both for tokens and cost. Turns with a 3-call tool loop
contributed only one call each.

**Cause:** `core/rpc/api.go:7990` usage hook fires from `HookPostLLM`
once per *persisted assistant message* and reads one `llm.Response`
(`capturedJournal.LookupCandidateUsage(text)` → fallback
`LastResponse()`), so intermediate tool-call iterations that do not
produce a persisted assistant text never reach `usageMgr.Add`. Same
hook feeds `last_usage_json` and `session.usage.updated`.

**Fix shape:** record usage per model call (the executor already counts
every call in `env.Counters` — `core/agentgraph/executor.go:642`), or
make the journal accumulate per-turn totals and record the sum once;
tests must cover a 3-iteration tool loop asserting the aggregate equals
the sum of the three responses. Keep `last_usage_json` = last call (it
drives the context bar) but make cumulative = sum.

## P2 — Tools of stopped MCP servers are advertised to the model and fail "server not in pool"

**Seen:** `filesystem__list_directory` → ERROR, `fetch__fetch` → ERROR
("stdio: server not in pool"); Capabilities shows Fetch "● STOPPED" with

### Behaviour changes not requested by the report

- **Prompt-kind user slash commands now send** the rendered body (plus
  text typed after the command) to the model as the user's turn, rather
  than showing it as a system bubble. Justification: a prompt command's
  body is an instruction for the model; rendering it inert is why
  `/bughunt <text>` did nothing useful. **Awaiting owner acknowledgement.**
- **`llm.ErrCancelled` matches `context.Canceled`** package-wide.
  Justification: adapters report a caller cancellation without wrapping
  the ctx error; every `errors.Is(err, context.Canceled)` branch (the chat
  runner's Stop arm first) must see it.
- **Per-message usage rows carry summed usage**: the row that follows
  one or more tool-only calls is billed with their usage, so its
  TokenMeterChip shows that turn-segment's total, not only its own call.

### Deferred

- **The seven existing orphan "Scheduled: Dogfood sentinel" sessions** in
  live databases are not cleaned up. A migration cannot tell a scheduled
  run's empty session from a session a user created and left empty
  without joining on `scheduled_chat_run_history`, and deleting user data
  in a migration needs its own destructive-migration coverage and owner
  sign-off; new failures no longer create them.
- **MCP demand-start** of an idle-stopped server: nothing in `core/mcp`
  idle-stops a server today, so there is nothing to wake; a failed or
  stopped server's tools are omitted from discovery instead.
- **Usage of a tool-only call when the turn ends right after it** (a Stop
  or failure before the next billed row) is not billed — it has no row to
  attach to. Fixing it needs a usage ledger not keyed on
  `session_messages`.
- **Model switch persistence is device-local** (`localStorage`): no
  backend binding stores a session's model, so served mode and other
  devices do not see a switch.
- **Scheduled-run recorded model** is resolved from the personal provider
  store's first profile (`DispatchModel`), which matches what the
  registry sends unless the registry's copy of that profile was changed
  after load (e.g. a fleet override); it can then differ from the model
  actually dispatched.
- **413 overflows** are classified `ErrTransient` (retried by the LLM
  retry middleware) and carry no window text, so they never receive the
  `request_too_large` verdict; they still take overflow recovery.
