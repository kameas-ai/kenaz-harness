Driven live through the desktop app (worktree harness-rel860, `wails dev`
with the dev signing pin) against the `dev` profile and fleet dev. Each

## P1 — Audit Log is empty by default for every user

**Seen:** Settings → Audit Log opens with Since = `2026-10-02` (7 days ago,
`defaultAuditSince()`), shows "No audit entries match the current filter"
and "Verified 0 entries — chain intact". Pressing **Clear** (Since empty)
lists 126 events including today's `branch.created`,
`fleet.context_published`, `fleet.config.applied`, `update.checked`.
Typing Since = `2026-10-08` by hand → empty again.

**Cause (two defects):**
1. `AuditView.vue` `richFilter` sends `since: "2026-10-02"` (date-only,
   `auditDateFilters.ts` returns `YYYY-MM-DD`) into
   `eventlog.FilterQuery.Since time.Time`. Wails cannot decode it —
   app log: `error parsing arguments: parsing time "2026-10-08" as
   "2006-01-02T15:04:05Z07:00": cannot parse "" as "T"` on
   `rpc.Bindings.Audit_Filter` (and once per keystroke while typing:
   `"2026-10-0"`). `refresh()` does `catch { seeded.value = []; }` — the
   exact "renders a default instead of an answer" fabrication the
   module comment above it says the view exists to stop (served-mode
   WP05 fixed only the served branch).
2. `core/rpc/views/audit/impl.go` `Filter()` calls
   `store.ByTimeRange(ctx, time.Time{}, time.Time{}, …)` and
   `matchesFilterQuery` checks Verbose / Kinds / FreeText only — Since,
   Until, ActorIDs, Resources, Outcomes are silently ignored. So even a
   well-formed date would not filter.

**Fix shape:** frontend sends RFC3339 bounds (`${d}T00:00:00Z`,
`${d}T23:59:59.999999999Z`); `Filter()` passes Since/Until to
`ByTimeRange` and applies them (plus actor_ids) on the ring path; the
view shows a visible error state on rejection and never renders an
empty list for a failed query. Tests: vitest on the wire shape + error
state; Go test on `Filter` honoring Since/Until (store path).

## P2 — Sent message resurrected as the composer draft

**Seen:** sent "Reply with exactly the word pong…" (Enter immediately
after typing). Navigated away and back; the composer held the sent text
again, so the next message persisted as one concatenated user turn
(`session_messages` rowid 351: 152 chars = both messages).

**Cause:** `useSession.ts` draft watcher:
```ts
watch(draft, (next) => {
  if (next === lastSavedDraft) return;          // ← returns BEFORE…
  if (draftDebounceHandle) clearTimeout(draftDebounceHandle); // …this
```
Type-then-Enter within 400 ms: no debounce has fired yet, so
`lastSavedDraft` is still `""`; the send clears `draft` to `""`, the
watcher early-returns without cancelling the pending debounce, and
400 ms later `saveDraft(sid, <sent text>)` persists the stale text. The
2026-10-05 fix covered the other ordering only.

**Fix shape:** cancel the pending debounce before the early return
(and flush `""` when the persisted value may differ). Regression test:
type, send within the debounce window, advance timers, assert the last
`saveDraft` call is `""`.

## P2 — Footer fleet chip shows `fleet: default-deny` after a verified bundle apply

**Seen:** footer reads `fleet: default-deny` all session. Audit log has
`fleet.config.applied` at 2026-10-08T00:50Z; fleet logs show
`fleet.config.fetch.success` every 5 min; `fleet/bundle_id.txt` exists.
**Cause:** `FleetHealthChip.vue` fetches once in `onMounted` and never
refreshes (ledgered as chip fetch-once staleness; now user-visible).
No hover/click affordance explains the states.
**Fix shape:** refresh on the fleet config-applied event (whatever the
frontend already receives for it) and on a slow interval / window focus;
add a `title` tooltip per state.

## P2 — Settings → Logs ring buffer is wiped by every model-list refresh

**Seen:** Logs page (2000-row ring) is almost entirely
`llm.model_info.dynamic_hit` DEBUG rows at one timestamp. App log:
14,280 `dynamic_hit` lines over 35 `refresh_kick`s = **408 rows per
refresh**, i.e. one refresh overwrites 20 % of the ring; the in-app log
is useless for the "debug failed MCP recipes" purpose its subtitle
claims.
**Fix shape:** emit one summary line per refresh (hits/misses/provider)
and keep per-model lines out of the ring (drop, or TRACE-level the ring
does not capture).
