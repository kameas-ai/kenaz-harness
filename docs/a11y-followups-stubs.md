## D-01 — Context menu (right-click) in LeftRail has no keyboard trigger

**View:** Sessions list (shell/LeftRail.vue)  
**Blocker:** The project context menu (Rename / Delete) is only reachable via right-click (`@contextmenu`). Keyboard users have no way to access these actions.  
**Suggested next step:** Add a `⋯` (three-dot) icon button to each project header row that opens the context menu on click/Enter/Space. The icon button must have `aria-label="Project options for {project.name}"` and `aria-haspopup="menu"`.  
**Labels:** `a11y`, `follow-up`

## D-02 — Drag-and-drop session reorder in LeftRail has no keyboard alternative

**View:** Sessions list (shell/LeftRail.vue)  
**Blocker:** Sessions can be dragged between projects but there is no keyboard-accessible move affordance. `dragstart`/`drop` handlers are mouse-only.  
**Suggested next step:** Implement a keyboard drag-and-drop pattern: when a session row is focused, Space/Enter enters "move mode" with visual indicator; arrow keys select the destination project; Space/Enter drops. Alternatively, provide a "Move to project" menu item via the D-01 context menu.  
**Labels:** `a11y`, `follow-up`

## D-03 — SlashAutocomplete listbox items are not focusable

**View:** Chat composer (components/chat/SlashAutocomplete.vue)  
**Blocker:** `<li role="option">` items have no `tabindex` attribute. The ARIA listbox pattern requires that options either be focusable or the listbox implement a roving tabindex. Currently keyboard navigation is handled by the parent textarea (Up/Down keys), but options themselves are not reachable by Tab.  
**Suggested next step:** Add `tabindex="-1"` to each `<li role="option">`. The parent ChatInput.vue already implements `ariaActivedescendant`-style selection via `activeIndex`; wire `aria-activedescendant` on the `<ul>` pointing to the id of the active option so screen readers announce the active option.  
**Labels:** `a11y`, `follow-up`

## D-04 — ArtifactPreview modal has no focus trap

**View:** Artifact preview (views/artifacts/ArtifactPreview.vue)  
**Blocker:** The modal is a home-grown overlay (not Radix-Vue Dialog). Tab focus can leave the modal and interact with the background content, violating WCAG 2.1.2 No Keyboard Trap (in the other direction — focus should be *retained* inside the modal).  
**Suggested next step:** Use Radix-Vue `<Dialog>` primitive (already vendored as `radix-vue` in package.json) to replace the home-grown overlay. The Dialog primitive provides focus trap, Esc dismiss, and restore-focus for free. Alternatively, implement a `useFocusTrap` composable using `inert` attribute on the background content.  
**Labels:** `a11y`, `follow-up`

## D-05 — ArtifactPreview modal does not restore focus on close

**View:** Artifact preview (views/artifacts/ArtifactPreview.vue)  
**Blocker:** When the modal closes, focus lands on `<body>` instead of the trigger button that opened the modal. Pair with D-04.  
**Suggested next step:** Capture `document.activeElement` before opening the modal; restore it in the `onClose` handler. Radix-Vue Dialog handles this automatically.  
**Labels:** `a11y`, `follow-up`

## D-06 — Audio/video artifact renderers have no captions

**View:** Artifact preview (views/artifacts/preview/renderers)  
**Blocker:** `<audio controls>` and `<video controls preload="metadata">` renderers in the binary preview registry have no `<track kind="captions">`. Wails WKWebView caption support has not been assessed.  
**Suggested next step:** Assess WKWebView WebVTT support. If supported, add a `<track kind="captions" default>` pointing to a companion `.vtt` file when one is present in the artifact scope. If not supported, document the Wails limitation and defer until a Wails version with full caption support is available.  
**Labels:** `a11y`, `follow-up`
