## 2. Audit Methodology

**WP01 — Static lint:**  
`eslint-plugin-vuejs-accessibility` v2.5.0 added to the ESLint flat config. Pre-existing `.vue` parser misconfiguration (tsParser applied directly to `.vue` files instead of vue-eslint-parser) was corrected as part of this work. Ten a11y rules enabled (six as `error`, four as `warn`). Full output: 48 errors + 228 warnings across 210 `.vue` files.

**WP02 — Axe-core component tests:**  
`vitest-axe` v0.1.0 integrated via `test-setup.ts`. Six new `*.a11y.test.ts` files added (one per major view group). ChatInput.test.ts extended with an axe assertion. All 7 axe tests pass.

**WP03 — Static structural sweep (manual VoiceOver / zoom not performed):**  
Sub-agent cannot execute VoiceOver, screen zoom, or visual contrast checks. Static analysis was performed by reading component source for ARIA roles, keyboard event handlers, focus management, and motion declarations. Items requiring human verification are marked **NMV** throughout.

**Wails/WebKit VoiceOver delta:**  
Wails wraps content in a WKWebView (macOS WebKit). VoiceOver behaviour may differ from Safari/Chrome for some ARIA patterns — specifically `role="switch"` announce cadence and live-region timing. All VoiceOver findings are **NMV** and should be verified with VoiceOver + Wails desktop build.

## 5. Persistent Guards (Axe-Core Test Files)

The following test files were added in WP02 and provide ongoing regression coverage:

| File | View group | Disabled axe rules |
|---|---|---|
| `src/components/chat/__tests__/ChatInput.test.ts` | Chat composer | `color-contrast` (happy-dom), `region` (isolated mount) |
| `src/views/sessions/__tests__/SessionsView.a11y.test.ts` | Sessions view | `color-contrast`, `region` |
| `src/views/settings/__tests__/SettingsView.a11y.test.ts` | Settings view | `color-contrast`, `region` |
| `src/views/artifacts/__tests__/ArtifactPreview.a11y.test.ts` | Artifact preview | `color-contrast`, `region` |
| `src/views/agentgraph/__tests__/GraphEditor.a11y.test.ts` | Workflow editor | `color-contrast`, `region` |
| `src/views/providers/__tests__/ProvidersView.a11y.test.ts` | Providers panel | `color-contrast`, `region` |

**Why `color-contrast` is disabled in all tests:** happy-dom v15 does not implement CSS computed style / layout. Contrast ratio is always reported as 0/0, generating false positives for every colored element. `color-contrast` must be verified with a real browser or accessibility scanner against a running Wails build.

**Why `region` is disabled in all tests:** Components are mounted in bare `<div>` wrappers in vitest. In production, every view is wrapped by the Shell grid (`<aside>`, `<main>`) which provides proper landmark regions. The `region` rule fires because the component tree lacks a containing landmark in the test environment.

## 7. Caveats

### Wails / WKWebView VoiceOver Delta

kenaz-harness runs in a Wails WKWebView on macOS. Known differences from Safari VoiceOver:

- **Live region timing:** `aria-live="polite"` regions may announce immediately rather than after a delay in some WKWebView versions. The streaming text surface uses `role="text"` (now removed) rather than an aria-live region. VoiceOver streaming announcement should be tested manually with `aria-live="polite"` on the message container.
- **`role="switch"`:** VoiceOver in WKWebView may announce the switch state differently than in Safari. Verify the "on/off" announcement cadence for the settings toggles.
- **Focus management in modals:** WKWebView focus trapping via `inert` attribute may not be fully supported in all Wails WebKit versions. The `Dialog` pattern (Radix-Vue) is preferred over home-grown modals for this reason.

### Disabled Axe Rules (all component tests)

- `color-contrast` — happy-dom has no CSS layout engine; all ratios are 0/0. Requires real browser verification.
- `region` — Component-level mounts lack Shell landmark wrapper. Not a real violation in production.
- `aria-allowed-role` (ChatInput, WP02 initial) — **Fixed** in WP04 (removed `role="group"` from `<form>`).
- `label` (ChatInput WP02 initial) — **Fixed** in WP04 (added `aria-label` to file input).
- `button-name` (SettingsView WP02 initial) — **Fixed** in WP04 (added `aria-label` to toggles).
- `label` (SettingsView WP02 initial) — **Fixed** in WP04 (added `aria-label` to inputs/slider).
- `label` (GraphEditor WP02 initial) — **Fixed** in WP04 (added `aria-label` to textarea).

## 8. Non-Goals

This audit explicitly does **not**:

- Claim or pursue **WCAG AA conformance certification**. This is a survey sweep to identify and prioritize findings.
- Create a **recurring per-PR a11y checklist**. The persistent guards are the 6 axe-core test files from WP02. No new CI gate was added.
- Add a **new CI gate for a11y violations**. The existing `npm run lint` and `vitest run` are the only CI changes.
- Add a **new charter directive** about accessibility going forward. This mission closes after WP06; ongoing a11y work is tracked in GitHub issues.
- Produce a **WCAG 2.x success criterion mapping**. Individual deferral items reference WCAG criteria where relevant but the audit does not produce a conformance statement.
